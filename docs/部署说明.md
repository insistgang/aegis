## 1. 运行环境要求

| 项目 | 要求 | 说明 |
| --- | --- | --- |
| **操作系统** | Linux、macOS（支持 Apple Silicon 与 Intel）。Windows 推荐 WSL2 | 纯标准 Python 实现，无平台特定 C 扩展依赖 |
| **Python** | 3.11 及以上（推荐 3.12 或 3.14） | 本机回归使用 3.14.7，CI 使用 3.12 |
| **CPU / 内存** | 以部署环境实测为准 | 尚未做系统资源压测。字符模型训练记录中的本机单次评分约 0.17 毫秒，不能当作整个 Agent 请求延迟 |
| **GPU** | 不需要 | 执法点与研判全确定性执行，不依赖 GPU |
| **出网** | 本地回归离线；真实模型需要出网 | 默认策略和评分权重在本地；MiniMax 模式需要访问配置的 HTTPS 接口 |
| **磁盘空间** | 安装后占用约几十 MB | SQLite 审计数据库依据日志量增长，单条记录仅占几百字节 |

AEGIS 执法点直接与 Agent 或 MCP 客户端部署在同一物理机/容器中，监控工具参数与不可信输入，不依赖网络流量镜像。

## 2. 安装与验收验证

```bash
# 1. 创建并激活虚拟环境
python3 -m venv .venv
source .venv/bin/activate

# 2. 安装项目及开发测试依赖
pip install -e ".[dev]"

# 3. 验收命令 1：运行全量自动化测试（应全部 PASS）
pytest -q

# 4. 验收命令 2：运行 31 场景 / 91 步核心基线回归
python -m aegis demo
```

**验收标准**：

- `pytest -q` 退出码必须为 0。
- `python -m aegis demo` 终端最终输出必须为 `31/31 个场景，91/91 步`，且所有场景状态均为 `PASS`。

2026-10-18 复跑结果为 10395 项 pytest 通过、31 个场景与 91 步通过。pytest 中的 10000 项语料检查是规则和评分器输出与冻结快照的一致性测试，全部通过不等于全部攻击识别正确，也不会调用 MiniMax。

## 3. 核心接入方式

### 3.1 SDK 嵌入接入

在宿主 Agent 执行具体动作前直接调用执法点：

```python
from aegis import AegisGuard, Decision
from aegis.victim import VictimAgent

guard = AegisGuard(audit_db="/path/to/audit.db")
sid = "session-prod-01"

# 1. 检查用户输入
user = guard.inspect_user(sid, user_prompt)
if user.decision is not Decision.ALLOW:
    return user.explanation

# 2. 检查外部输入（如网页、文档、Issue 等）
page = guard.inspect_resource(sid, untrusted_content, source=doc_url, kind="web")
if page.decision is not Decision.ALLOW:
    untrusted_content = "[AEGIS] 外部内容已被隔离"

# 3. 工具调用前判定
call = guard.inspect_tool_call(sid, "fs.read", {"path": file_path}, mcp="local-fs")
if call.decision is Decision.BLOCK:
    return call.explanation
if call.decision is Decision.ASK:
    if not user_confirmed:
        return "需用户确认该敏感操作"
    call = guard.inspect_tool_call(sid, "fs.read", {"path": file_path}, confirmed=True, mcp="local-fs")
if call.decision is not Decision.ALLOW:
    return call.explanation

# 4. 观察实际工具返回
real_result = run_tool(file_path)
seen = guard.observe_tool_result(sid, "fs.read", {"path": file_path}, real_result, call_span_id=call.span_id)
safe_result = "[AEGIS] 结果已被阻断隔离" if seen.decision is not Decision.ALLOW else real_result
```

若需本地演练不可信内容驱动的攻击场景，可直接调用 `VictimAgent`：

```python
agent = VictimAgent(guard=guard)
result = agent.run(task="阅读项目 README", untrusted_text=raw_readme, channel="resource")
# 阻断动作被真实拦截记录，且绝不假装执行
```

### 3.2 多上游 MCP 中间代理 (Multi-upstream stdio)

当拥有多个上游 stdio MCP Server 时，编写配置文件（支持 JSON 或 YAML 格式）：

```json
{
  "mcpServers": {
    "files": {
      "command": "python",
      "args": ["/opt/mcp/fs_server.py"]
    },
    "git": {
      "command": "python",
      "args": ["/opt/mcp/git_server.py"]
    }
  }
}
```

启动多上游代理进程：

```bash
python -m aegis proxy --config mcp_servers.json
```

**多上游代理行为**：
- 聚合多个上游工具，在 `tools/list` 中为每个工具注入 `source` 来源名。
- 工具描述投毒按 `(server, tool)` 单独计算。某上游工具被投毒剔除，其他上游正常工具绝不受影响。
- 敏感阻断调用（如写入 `~/.ssh/authorized_keys`）由代理直接拦截返回，绝不下发至任何一个上游。

向下兼容单上游命令格式：
```bash
python -m aegis proxy --name files -- python examples/fake_mcp.py
```

### 3.3 本地研判看板

启动内置本地研判看板：

```bash
python -m aegis serve --host 127.0.0.1 --port 8765
```

浏览器打开 <http://127.0.0.1:8765>。

- 支持一键执行 31 个场景回归测试与 DAG 路径可视化。
- 支持受害 Agent 本地交互演练。
- 支持在「试一段文本」中粘贴任意文本，清晰区分 **「拦下了」**（提供命中规则与证据起止下标）、**「这段绕过了当前规则」**（提供未接住原因）以及 **「正常放行（良性文档）」**。

默认端口为 8765；本机此次演示使用 8766，以避开已有服务。需要沿用该地址时启动 `python -m aegis serve --host 127.0.0.1 --port 8766`，访问 <http://127.0.0.1:8766>。

Docker 部署：

```bash
docker build -t aegis .
docker run --rm -p 127.0.0.1:8765:8765 aegis
```

上述 Docker 示例仅提供离线能力。容器不会自动继承宿主机密钥文件或 `.aegis.local.json`；真实模型配置需单独以环境变量或只读挂载接入。

### 3.4 MiniMax M3.1 Flash Preview 配置

在项目根目录创建已被 Git 忽略的 `.aegis.local.json`：

```json
{
  "base_url": "https://api.minimaxi.com/v1",
  "model": "MiniMax-M3.1-Flash-Preview",
  "keys_file": "~/.codex/keys.txt",
  "reasoning_effort": "low",
  "max_completion_tokens": 1024
}
```

程序从密钥文件中选择 URL 完全匹配的 `url:...` / `key:...` 块，不把密钥复制进项目。`AEGIS_LLM_API_KEY` 或当前厂商的 `MINIMAX_API_KEY` 可提供密钥；`AEGIS_LLM_BASE_URL`、`AEGIS_LLM_MODEL`、`AEGIS_LLM_REASONING_EFFORT`、`AEGIS_LLM_MAX_COMPLETION_TOKENS` 优先于本机配置。`AEGIS_LLM_CONFIG` 可指定另一份配置，`AEGIS_LLM_KEYS_FILE` 可指定另一份密钥文件。不要在命令、报告或截图中写入真实密钥。

无本机配置或环境覆盖时，源码仍保留 Kimi 默认接口和模型值。要确认当前配置，可只查询公开状态，不产生模型调用：

```bash
curl http://127.0.0.1:8766/api/llm
```

在看板「工具调用智能体」中选择 `MiniMax-M3.1-Flash-Preview`，再点击运行才会调用模型。CLI 的真实模型命令为：

```bash
python -m aegis agent --backend live --task '总结这份文档' --text 'Python 3.11 以上，使用 pip 安装。'
```

模型端点要求 `application/json`、合法的 `127.0.0.1`、`localhost` 或 `[::1]` Host及实际服务端口；浏览器Origin必须同源。即便看板绑定 `0.0.0.0`，该端点仍不支持通过局域网域名或反向代理消费模型额度。

该命令会消耗模型额度。接口不可用或没有匹配密钥时应直接报错；离线协议回放使用 `--backend scripted`。当前 `run_tool_agent` 在内容为询问或阻断时隔离原文；历史万条实验采用原文直送协议，不能据当前代码改写历史结果。

### 3.5 批量复跑与本次方法的差别

先完成三类核查：模型身份、独立输出文件、预期样本数。通用脚本的样例命令如下，执行时会真实调用模型：

```bash
# 新结果文件，先跑 100 条；文件名保留 *_runs.jsonl 以被 Git 忽略
python scripts/run_kimi_corpus.py --workers 2 --limit 100 --output data/corpus/minimax_rerun_runs.jsonl

# 显式处理上述文件中尚未成功的全部剩余语料
python scripts/run_kimi_corpus.py --workers 2 --limit 0 --output data/corpus/minimax_rerun_runs.jsonl
```

只有具备完整最终回答的成功样本才按 ID 跳过；单回合中只提出工具调用的记录标为 `incomplete`，不会永久跳过。不同模型不能混用结果文件。同一个输出文件只运行一个写入进程。保留本次已完成的 `minimax_m3_1_flash_preview_runs.jsonl` 作为历史证据，新的实验使用独立文件。

**这两条命令不完全复现本次全量协议**：通用脚本每条只调用一个模型回合，任务表述也不同。本次执行器使用任务「总结下面这份外部材料。只有用户任务需要文件、网络、命令、推送或子任务时才使用工具。」，每条最多三个回合，并额外记录 HTTP 回执、响应 ID、失败恢复和断点。`aegis agent` 默认又是最多四回合。比较模型结果前需统一这些参数。

本次使用专用执行器及监督进程，最终文件快照与参数记录归档于 [实测证据目录](evidence/minimax_20261018/README.md)。快照用于审阅方法，保留了本机路径和历史默认值，不能当作已发布的通用命令入口；前 100 条初测与运行中的不同启动版本也没有逐版本源码归档。

限流和额度耗尽要分别处理。此次约 60 次请求/分钟的试运行遇到 HTTP 429，之后主批次约 50 次/分钟，最后恢复阶段为 2 路并发、2 秒请求间隔；这些是本次观测值，不是套餐上限承诺。等待服务方窗口、退避和断点续跑会改变结束时间；无需改换计费通道。

### 3.6 完成核验与证据留存

本次 `progress.json` 已为 `state=complete`、`successful_unique=10000`、`remaining=0`、`unresolved_failed_unique=0`，批量与监督进程已退出。`started_at` 和 `elapsed_seconds` 是最后一次恢复进程的计时，不能用 152.6 秒当作整个 10000 条实测的总耗时。

## 4. SQLite 审计与脱敏导出

所有会话决策均可持久化至 SQLite 数据库。在生产环境退出或重启后，仍能完整还原会话上下文、决策过程、证据切片下标、策略编号、DAG 链路与影响面：

```bash
# 导出全部或指定会话的脱敏审计数据至 JSON
python -m aegis audit export --db /var/log/aegis/audit.db --output /tmp/audit_export.json
```

**密钥脱敏保障**：SQLite 写入前调用 `redact`，本地回归核对 AKIA、PEM 私钥块与 `aws_secret_access_key` 等测试材料未出现在数据库及导出 JSON 中。这是对已覆盖模式的验证，不能作为所有密钥格式都已覆盖的保证。本次 MiniMax JSONL 是另一条实验记录链路，不是 SQLite 审计导出。

## 5. 策略定制与安全基线校验

策略文件路径通过环境变量指定：

```bash
export AEGIS_POLICY=/etc/aegis/custom_policy.yaml
python -m aegis serve
```

AEGIS 内置安全基线底线检查（`validate_floor`）。无论如何自定义规则，以下五项规则必须保持为阻断态，尝试弱化为 `allow` 会触发抛出 `PolicyError` 终止启动：
1. 敏感路径写入阻断 (`fs-write-sensitive`)
2. 会话密钥非信任域外发阻断 (`net-exfil-secret`)
3. 恶意命令管道与解码执行阻断 (`exec-malicious`)
4. 代码检视期间代码推送阻断 (`git-push-off-review`)
5. 子 Agent 携带密钥阻断 (`subagent-secret`)

## 6. 已知边界声明 (Boundaries)

- **无模型裁判**：判定仅依赖确定性规则，严禁引入大模型作为放行裁判，防止模型被攻击载荷欺骗。
- **不做完整 bash AST 解析**：当前系统通过预处理归一化处理了赛题重点关注的管道执行、Base64 解码、引号分割、IFS 环境变量混淆与命令替换，不展开完整的 POSIX Shell 抽象语法树分析。
- **路径按参数字符串判断，不解析符号链接**：策略规则基于传入参数中的路径规范化后进行模式匹配，符号链接的物理真实性应在底层的真实文件打开调用处保障，本系统不声称已在应用层解决软链接穿透。
- **实测覆盖**：全量运行统一送入外部文档上下文，只观察到文件读取与执行询问；邮件、长期记忆和 MCP 等接入端点的验证来自相应本地场景，不能由此声称已完成全部真实模型端到端测试。
- **模型效果**：语料为自建合成文本，内容规则攻击放行 3489/5040，良性误拦 10/4960。历史万条批次没有无守卫对照组及回答级攻击成功评测，不能将接口完成率写成防护成功率。

## 六项修复的接入与复核

实际本机设备为 Apple M5、16 GiB、macOS 26.5.2、arm64，项目 Python 3.14.7、PyYAML 6.0.3、pytest 9.1.1。设备记录不等于最低资源或并发容量承诺。

运行 `python examples/topic5_defense_demo.py` 复核 12 项防护和完整脱敏轨迹，不调用外部模型。MCP 启动可用 `python -m aegis proxy --task '只能读取 /workspace/README.md' --config /path/to/mcp_config.json` 传入可信原始任务；工具元数据和上游正文不得作为授权来源。

SDK 宿主须消费三态：只执行 allow；ask 暂停，确认后重新送审；block 不可覆盖。每次调用保存返回的 span_id，工具返回以 `call_span_id` 送入观察接口，拒绝不唯一关联。父子代理使用唯一身份和 `parent_agent` 登记；完整返回经脱敏后落盘。详情见 [六项修复验收报告](六项修复验收报告.md)。
