# 部署说明

## 1. 运行环境

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Linux、macOS。Windows 可以用 WSL |
| Python | 3.11 及以上。镜像里用 3.12 |
| CPU / 内存 | 1 vCPU、512 MB 足够。检测是规则和字符串匹配，不是模型推理 |
| GPU | 不需要 |
| 出网 | 不需要。默认策略不调用模型 API |
| 磁盘 | 安装后约几十 MB |

执法点跟 Agent 或 MCP 客户端部署在同一台机器上。它看的是工具参数和读进来的文本，不镜像网络流量。

## 2. 安装

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
pytest -q
aegis demo
```

`aegis demo` 应打印 `31/31 个场景，91/91 步`。不是这个结果就不要接进线上 Agent。

只跑演示、不跑测试时，可以不装 `pytest`：

```bash
pip install -e .
```

## 3. 三种接法

### 3.1 SDK

宿主在执行工具之前调用守卫。阻断就不要执行；询问就停下来等用户；工具返回先交给 `observe_tool_result`，通过了再送进模型。

```python
from aegis import AegisGuard, Decision

guard = AegisGuard()
sid = "session-42"

user = guard.inspect_user(sid, user_text)
if user.decision is Decision.BLOCK:
    return user.explanation

page = guard.inspect_resource(sid, html, source=url, kind="web")
if page.decision is Decision.BLOCK:
    html = "[AEGIS] 该网页已隔离"

call = guard.inspect_tool_call(sid, "fs.read", {"path": path}, mcp="local-fs")
if call.decision is Decision.BLOCK:
    return call.explanation
if call.decision is Decision.ASK:
    if not user_confirmed:
        return call.explanation
    call = guard.inspect_tool_call(sid, "fs.read", {"path": path}, confirmed=True)

result = real_fs_read(path)
seen = guard.observe_tool_result(sid, "fs.read", {"path": path}, result)
model_text = "[AEGIS] 结果已隔离" if seen.decision is Decision.BLOCK else result
```

记忆写入用 `inspect_memory(..., op="write")`。工具注册用 `inspect_tool_description`。子 Agent 派发当成工具 `agent.spawn`，参数里放 `child` 和 `prompt`。

会话号由宿主生成。同一个任务的用户消息、工具和子 Agent 必须用同一个 `sid`，污点和意图才接得上。

### 3.2 MCP 中间代理

代理使用 MCP stdio 的 `Content-Length` 分帧。把原来启动上游 server 的命令交给 `aegis proxy`：

```bash
aegis proxy --name github -- python /opt/mcp/github_server.py
```

客户端的 MCP 配置改为启动这条命令，而不是直接启动上游。`--name` 会出现在轨迹的 MCP 节点上，多个上游就起多个代理进程，名字分开。

行为：

- 带注入的工具描述不会出现在 `tools/list` 里。
- 被阻断的 `tools/call` 不会转发给上游。
- 未确认的询问返回 `AEGIS_ASK`。客户端确认后在参数上加 `"_meta": {"aegisConfirm": true}` 再发一次。
- 工具返回里的注入会被换成隔离说明。

参考上游：

```bash
export AEGIS_FAKE_LOG=/tmp/aegis-upstream.log
aegis proxy --name files -- python examples/fake_mcp.py
```

`examples/fake_mcp.py` 只回显工具名，用来确认阻断没有落到上游。

### 3.3 研判看板

```bash
aegis serve --host 127.0.0.1 --port 8765
```

浏览器打开 <http://127.0.0.1:8765>。默认只监听本机。看板会回放内置场景，也会对粘贴的文本做一次检查。它不是给公网用户用的，前面不要直接挂反向代理到公网。

Docker：

```bash
docker build -t aegis .
docker run --rm -p 127.0.0.1:8765:8765 aegis
```

镜像里的监听地址是 `0.0.0.0`，端口发布仍然绑在宿主机的 `127.0.0.1`。

## 4. 策略

默认策略：`src/aegis/data/default.yaml`。

替换：

```bash
export AEGIS_POLICY=/etc/aegis/policy.yaml
aegis serve
```

加载时会检查赛题基线还在，而且仍是阻断：

- `fs.write` 必须覆盖 `.ssh`、cron、LaunchAgents
- `net.fetch` 必须能阻断“非信任域名 + 会话密钥”
- `exec` 必须阻断下载管道和解码执行
- `git.push` 在代码检视时必须阻断
- `agent.spawn` 带密钥必须阻断

把这些改成 `allow`，或者删掉，进程会在加载策略时抛 `PolicyError`，不会静默变成一个更松的守卫。信任域名和额外的询问规则可以加。

改完策略要重启进程。SDK 是构造 `AegisGuard()` 时读文件，代理和看板也是。

## 5. 日志和密钥

轨迹导出、看板 JSON、`aegis show` 都会抹掉识别到的密钥材料。检测用的原文针只留在进程内存，用来判断下一次外发，不写报告。

不要把看板日志级别调到打印完整工具参数后落到集中日志。代理自己打到标准错误的内容不包含上游返回正文。

## 6. 建议的接法

企业内部可以同时用两种：

1. 编码 Agent 所在的开发机或 CI 上跑 MCP 代理，挡住第三方 MCP server 的描述投毒和工具滥用。
2. 自建 Agent 平台用 SDK 包住记忆读写和子 Agent 派发。MCP 代理看不见平台自己的记忆库。

两者共用一份策略文件。审计库如果要落多实例轨迹，把 `guard.snapshot(sid)` 的 JSON 送到现有的 SIEM 即可，不需要改检测逻辑。

## 7. 已知边界

- 代理是同步的请求-响应模型，适合 stdio MCP。HTTP/SSE 传输可以复用 `McpGate`，传输层要另接。
- 路径策略看参数字符串。符号链接要在执行 `open` 的那一层再判一次。
- 单进程内存保存会话。进程退出后污点和描述哈希消失，这是预期行为，不是审计库。
