# 作品提交文件构建

本次PDF与Word使用 [同一份作品正文](作品提交文档.md)，避免原稿Word为摘要、PDF为完整稿的差异。正文保留五个大章节；数据图由 `scripts/build_submission.py` 依据冻结数据绘制。

## 工具与输入

本机使用Codex主运行时提供的Python、python-docx、Pillow、LibreOffice和Poppler，Markdown结构由Pandoc解析。文档工具不是核心程序依赖；普通使用者安装项目运行规则与测试，不需要安装这套排版依赖。

构建脚本沿用参考Word的A4单节页面和运行页眉页脚，替换全部正文、表格和图。参考副本在本机父目录 `.tmp/aegis-submission-20261018` 保留，不覆盖原始备份。维护时也可将最新Word作为参考，输出到另一文件。

示例流程：

```bash
python scripts/build_submission.py \
  --reference-docx 'output/docx/尹纪元+神盾AEGIS+作品文档.docx' \
  --output tmp/pdfs/rebuilt.docx \
  --pytest-count 10395
```

该示例需要已准备文档依赖的Python、Pandoc和macOS宋体/黑体。先更新正文的测试计数并完成验证，再重建；不能仅改命令数字而保留旧正文。

## 渲染与检查

本次使用文档技能的 `render_docx.py --emit_pdf` 从Word生成PDF和逐页PNG。渲染依赖运行时的LibreOffice及Poppler。针对本机headless运行时，通过临时 `FONTCONFIG_FILE` 明确加入 `/System/Library/Fonts`、`/System/Library/Fonts/Supplemental` 和 `/Library/Fonts`，解决首轮中文字体缺失问题；没有修改运行时或系统字体目录。

本轮随攻防对照补充重新渲染并逐页检查。最终页数、已检查页数、文档指纹及代码基线写入交付校验清单；历史18页版本保留备份。排除空页、缺字、重叠、表格越界和图注错位，页码应连续。

同时检查了关键数据、五个章节、历史/交付版测试数的区别、旧测试语句移除、PDF文本边界、完整Word表格和6幅插图。PDF直接由该Word转换，不另写一份PDF正文。

## 交付与同步

交付版PDF、Word、源码与数据包先写项目 `output` 目录，核对后替换桌面“研网赛提交”的对应文件和源码副本。旧PDF、Word、ZIP与源码目录已经备份。校验清单记录代码基线、文件SHA256和验证结果。

原始实测JSONL虽然被Git忽略，本次压缩包单独收录；散文件指纹与报告一致。密钥、本机配置、虚拟环境、运行锁、缓存和Git内部文件均排除。文档和打包变更通过后续提交同步，代码基线仍可独立定位。
