# 六项安全能力修复方案

## 目标与授权范围

根据 2026-10-18 赛题对照审查及用户要求，修复工具别名、秘密传递、策略降级、任务对齐、溯源和长文本六项问题。以实际 SDK、MCP 门禁、离线模型循环和 SQLite 导出行为验收，不以新增字段或图示代替功能。历史 MiniMax 一万条响应保持原样，本轮不调用付费模型。

## 设计边界

- 保留 Python 3.11+、PyYAML、pytest 技术栈，不增加核心运行依赖，不引入模型裁判。
- SDK 和 MCP 使用同一确定性门禁；工具别名与参数结构归一后执行语义策略，并保留原工具名称。未知语义不声称能自动理解，提供明确的映射及保守处理边界。
- 五项强制阻断基线在运行时独立于可编辑规则执行；配置加载拒绝以额外条件缩小保护范围的伪基线，确认不得覆盖 block。
- 敏感文件返回按来源追踪完整秘密及配置值；检查原文与有界可逆编码变体，审计必须同步擦除这些值。不能声称覆盖任意加密或隐写。
- 任务对齐结合合法用户消息中的路径/操作约束、工具参数、提交的计划和已观察调用序列。显式的“只能读取指定文件”不能因工具名为 fs.read 而绕过。未明确的自然语言意图不冒充完整语义理解。
- 调用使用明确 call_id；返回关联对应调用。子代理按唯一 agent_id 和 parent_agent 注册；完整返回经脱敏后持久化，不再仅保存预览。模型循环和 MCP 都接入返回观察接口。
- 来源提供原文字符区间与版本化 token 区间及来源标识。默认使用无外部依赖、覆盖完整原文的 Unicode 审计分词器；允许注入指定 tokenizer。默认审计 token 不冒充服务商模型或账单 token。
- 全文检查不能跳过中段；全文规范化保留原文偏移，不因超长空白跨越分块边界而漏检。跨消息拼接保留各段来源，不能把前一来源的字符全部归给后一来源。

## 文件与接口约定

源码位于 src/aegis，测试位于 tests，实测数据位于 data/corpus，正式文档位于 docs，提交文件位于 output。新增函数沿用类型注解、关键字参数和中文简短说明，例如 `resolve_tool(tool: str, args: dict) -> tuple[str, dict]`。

1. 工具与策略任务：新增 tool_semantics.py 的 resolve_tool；修改 policy.py；专用测试 test_tool_semantics.py、test_policy_floor.py。Coordinator 在 guard.py 调用 resolve_tool，保留原调用参数供审计。此任务不改 guard、features、MCP 或其他任务文件。
2. 秘密任务：修改 features.py，必要时新增 taint.py；提供 harvest_secret(source, text, path) -> SecretRecord | None，以及 redact_session(value, records)；保留 SecretRecord 的现有字段与 carries_secret 接口。Coordinator 接入 _harvest 和审计。专用 test_secret_taint.py。
3. 对齐任务：修改 intent.py，必要时新增 alignment.py；提供 evaluate_alignment(intent, task_messages, tool, args, history, plan) -> dict，字段 deviation、block、reasons；保留既有 classify/deviation 接口。专用 test_task_alignment.py。Coordinator 接入用户消息、计划和执行序列。
4. Coordinator：guard、session、trace、models、audit、agent、mcp_gate、proxy、CLI；新增 provenance；长文本与调用关联集成测试；最终报告和打包。

Worker 仅拥有各自列出的写入范围，不修改共享文件、提交 Git、调用付费接口或继续委派。所有人保留其他人的改动。依赖接口变更先通知 Coordinator。
